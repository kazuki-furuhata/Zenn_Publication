株式会社 MBK デジタルの古畑です。

2026 年 5 月 21 日 (木) に Google 渋谷オフィスで開催された 第 14 回 Leader's Meetup に参加してきました。
さらに今回はありがたいことに、参加者 LT 枠で登壇する機会もいただきましたので、参加レポートと合わせて登壇内容についてもご紹介します。

## 2. Leader's Meetup とは
### 概要
Leader's Meetup は、Google Cloud を活用するユーザー企業・パートナー企業のエンジニアやリーダーが集まる、Google Cloud 主催のクローズドなネットワーキングイベントです。

- 渋谷の Google オフィスで定期開催
- NDA ベースで、各社の赤裸々な技術課題や事例を共有できる
- Beer Bust 形式（お酒を飲みながらのカジュアルな会）で、双方向の対話に重きが置かれている
- Google Cloud のカスタマーエンジニアが各テーブルでファシリテートしてくれる

参加者の方による過去回のレポートも公開されており、雰囲気を掴むのに参考になります。

受付を済ませて会場に入ると、24 階のイベントスペースから渋谷の夜景が見える中、すでにドリンク片手に歓談している参加者の姿があり、いい意味でゆるい立ち上がりでした。

### Google Cloud からのアップデート
冒頭の Google Cloud さんからのアップデートは、ラスベガスで開催された Google Cloud Next '26 の Recap を軸に紹介されました。
 
NDA 領域に踏み込む話も含まれていたため詳細は割愛しますが、個人的に印象的だったのは、**「Agent をどう作るか」から「Agent をどう運用・統治するか」へ Google Cloud の関心の重心が明確に移っている**点でした。
後述する自分の LT のテーマともダイレクトに関係するアップデートで、聞きながら頭の中で「これは LT の文脈と完全に噛み合うな…」とニヤニヤしていたのは内緒です。

### お客様による Lightning Talk
Google さんの発表が終了したのち、 4 人の参加者による LT が行われました。
他社の登壇内容には触れませんが、いずれも実プロダクトでの生成 AI 活用の生々しい話で、「同じ壁にぶつかっているのは自分たちだけじゃない」と感じられる、Leader's Meetup らしい中身の濃いセッションでした。
 
自分の LT については、本記事のメインとして後段で改めて詳しくご紹介します。

### アンカンファレンス
LT のあとは、参加者同士で 3〜4 人のグループに分かれてのアンカンファレンスです。
各テーブルには Google Cloud のカスタマーエンジニアの方が入って議事録を取りながらファシリテートしてくれるので、初対面同士でもスムーズに議論が始まるのが Leader's Meetup の良さです。
 
テーブルでの具体的なやり取りは書けませんが、テーマレベルで言えば
 
- **AI エージェントを社内にどう浸透させるか**
- **セマンティックレイヤーをどの粒度で整備するか**
- **LLM の評価・ハルシネーション対策の運用知見**

といった論点が複数のテーブルで盛り上がっていた印象です。

各社が直面している課題のリアリティと、それに対する打ち手のバリエーションの広さが本当に学びになる時間でした。
「自分たちのアプローチが標準解に近いのか、それとも独自路線なのか」を一次情報で確認できる場というのは、思っているよりも貴重です。

### ネットワーキング
クロージング後はそのまま立食でのネットワーキングへ。
LT を聴いてくださった方が声をかけてくださる場面も多く、「うちも同じ問題で悩んでいる」「LookML のセマンティックレイヤーをどう運用しているか聞きたい」といった具体的な相談から、純粋に Looker / Gemini Enterprise の運用 Tips まで、立ち話とは思えない密度の会話が続きました。
 
普段は X (旧 Twitter) や登壇イベントで一方的にお見かけしていた方と、Beer Bust 形式の気軽さもあって率直に技術談義ができたのも収穫でした。
NDA が結ばれている場だからこそ、「事例として外に出せない部分」も含めて話せるのが Leader's Meetup の最大の価値だと改めて感じています。

## 3. 【LT 登壇】「データアナリスト」の仕事はどう変わるか 〜 Looker BI Agents × Gemini Enterprise Agent Platform が再定義する分析の現場 〜
### なぜこのテーマを選んだか
LT のオファーをいただいた際、Google Cloud Next '26 で発表された **Gemini Enterprise Agent Platform** と **Looker BI Agents** をどう実プロジェクトに取り込むか、という議論が社内で盛り上がっていました。

特に、データ分析の現場では以下のような「あるある」が長年の課題として残っていました。
 
1. **ダッシュボードが意思決定に使われない**
2. **アナリストが『クエリ実行係』化する**
3. **結局アナリストに質問が集中する**

これは業界で **レポートファクトリー** と呼ばれるアンチパターンです。
ビジネス側からの問いに対して、静的なダッシュボードを量産することで答えようとする構造のことで、組織が成長するほど詰まっていく宿命を抱えています。
 
冒頭、会場にこう問いかけました。
 
> 「ダッシュボード、見てますか？ダッシュボード、見られてますか？」
 
…会場の苦笑いがちょうどよかったです。

### BI の位置づけが変わった
Next '26 で発表された 2 つの新基盤は、この「レポートファクトリー問題」に正面から答えるものでした。

**Gemini Enterprise Agent Platform**
 
AI エージェントを「作る・育てる・統治する」ための統合基盤で、Vertex AI の進化形として再構成されたプラットフォームです。
 
- Agent Development Kit (4 言語サポート)
- Agent Runtime / Memory Bank / Marketplace

「エージェントを 1 個作って終わり」ではなく、組織として複数エージェントを安全に運用するためのレイヤーが揃ったことが大きな転換点だと感じました。

**Looker BI Agents**
 
BI に自律的なエージェント能力を統合する一連の新機能群です。
 
- Dashboard Agents
- Agentic Workflows
- Conversational Agents 強化版 / Open BI + MCP

ここがポイントなのですが、**BI は「見るもの」から「動くもの」へ変わる** ということを意味しています。
ユーザーがダッシュボードを開きに行かなくても、エージェント側から「これ見てください、こうなってますよ」と知らせてくれる世界です。

### 弊社 MBK デジタルでの取り組み
弊社では、この新しい BI の姿を実装するためのアーキテクチャを以下のような 4 層構造で整理しています。
 
```
┌─────────────────────────────────────────┐
│ ビジネスユーザー（自然言語で対話）          　│
├─────────────────────────────────────────┤
│ Gemini Enterprise Agent Platform        │
│ （マルチエージェント連携）　　　　　　　　　　　│
├─────────────────────────────────────────┤
│ Conversational Analytics + ADK          │
│ （Looker BI Agents）　　　　　　　　　　　　 │
├─────────────────────────────────────────┤
│ LookML セマンティックレイヤー          　   │
│ （= AI エージェントの「事実の根拠」）　　　　　│
└─────────────────────────────────────────┘
```
 
ポイントは一番下の **LookML セマンティックレイヤー** です。

エージェントが自然言語クエリを受けても、最終的に「正しい数字」を返さなければ意味がない。
その正しさを担保する場所が、これまで地道に整備してきたセマンティックレイヤーです。
 
AI 時代になって LookML の価値が、むしろ上がっている。これは現場の実感でもあります。

### Before / After で見る分析体験の変化
実装に向けて取り組んでいる体験の変化を、Before / After で整理するとこうなります。
 
| Before（従来 BI） | After（Agentic BI） |
| --- | --- |
| ユーザーがダッシュボードを開く | **エージェントが異常を検知** |
| 数値をよく見て問題に気づく | **原因となる仮説を自動で提示** |
| 質問はアナリストに集中 | **自然言語による対話で疑問を解消** |
| ネクストアクションは別会議で議論 | **推奨ネクストアクションが自動で提示** |
 
これまで「ユーザーがダッシュボードに来てくれる」ことを前提に設計されていた BI が、エージェント側からプッシュ型で動き出す構造に変わります。

### データアナリストは『消える』のか？
ここで多くの方が気になるであろう問い、「じゃあデータアナリストの仕事は消えるの？」について。
答えはハッキリしていて、**NO. むしろ、より高次の役割へシフトする** です。
 
| Before | After |
| --- | --- |
| クエリの実行者 | **エージェントの設計者** |
| レポートの作成者 | **セマンティックレイヤーの整備者** |
| 数値の伝達者 | **エージェントの監督者** |
 
新しい競争力はセマンティックレイヤーの整備力に集約されていきます。
「エージェントを動かす土台」を誰が、どれだけ丁寧に作れるか。ここで差がつきます。

弊社では、コンサルティング・受託開発による実装支援と、データ人材育成講座 BizSchola での教育の両面から、この役割の浸透に取り組んでいます。

### 登壇しての所感
5〜7 分という短い枠で詰め込みすぎないか不安でしたが、Beer Bust 形式ということもあって、聴いてくださる方の反応がダイレクトに伝わってきて、登壇していてとても楽しい時間でした。
 
特に「アナリストは『エージェントを育てる人』へ」のスライドで会場の頷きが揃ったのが印象的で、「Agentic BI への移行の中で、アナリストという職種をどう位置づけ直すか」という問いは、各社のデータ組織が共通して向き合っているテーマなのだと改めて確信できました。
 
登壇後の懇親会では、複数の方から「セマンティックレイヤーの整備をどこから始めればいいか」「既存ダッシュボード資産との共存をどう考えるか」といった、まさに移行期ならではの実装寄りの相談をいただきました。
LT を通じて議論の入り口を作れたことが、その後のネットワーキングの時間をぐっと濃くしてくれた感覚があります。

## 4. まとめ
第 14 回 Leader's Meetup の参加 & LT 登壇レポートでした。
 
普段はなかなか接点のない他社のトップエンジニアの方々と、NDA という安心感のある場で踏み込んだ議論ができるのは、Leader's Meetup ならではの体験です。
LT 登壇という形で自分の取り組みを共有できたことで、その後の対話の入り口も作りやすく、登壇しに行くという参加スタイルは強くおすすめできます。
 
今回お伝えした 3 つのメッセージ、
 
- **BI は『見るもの』から『動くもの』へ**
- **競争力はセマンティックレイヤーの整備力**
- **アナリストは『エージェントを育てる人』へ**

は、Next '26 を経たこれからの数年、データ活用に関わる全てのエンジニア・アナリストにとって避けて通れないテーマになっていくはずです。
弊社 MBK デジタルとしても、実装支援と人材育成の両輪で、この変化を後押しできるパートナーであり続けたいと思っています。
 
主催してくださった Google Cloud の皆様、参加者の皆様、本当にありがとうございました。
次回もぜひ参加させていただきたいです🍻
